# PRD 验收记录

先拆 PRD，再从已授权的入口进入应用。用真实浏览器做只读发现并确认页面，通过校验后再执行该页的业务操作。旧运行或导入的 CSV 可以查看和补录，缺少下列记录时质量门禁不予放行。

## 1. 拆分验收点

在 `requirements.json` 保留 PRD 文档及条款位置。把可独立失败的行为拆成独立验收点。例：姓名查询和手机号查询各记一项，新增校验和保存后回查各记一项。

```json
[
  {
    "id": "REQ-003",
    "source": "物料 PRD §REQ-003",
    "criteria": [
      {"id": "AC-031", "page": "PAGE-001", "rule": "新增后列表金额等于数量乘单价"}
    ]
  }
]
```

验收点默认必测。PRD 未定口径、缺适用账号或待确认页面时保留验收点，未定规则可用 `"status":"pending"`，不得直接删掉。明确不属于本次必测范围时可写 `"required":false` 并填 `scope_note`，说明 PRD 或用户确认的依据。

在 `test-cases.json` 写用例、步骤和逐验收点预期。按风险补正常、边界、异常、角色与回归场景。一个验收点可以有多条计划用例，所有关联用例的有效实测均通过才算该验收点通过。数值单位、精度和排序规则在计划时固定。用例期望值须在执行前写入，禁止看到结果后倒填。

```json
{
  "cases": [
    {
      "id": "TC-031",
      "req": "REQ-003",
      "page": "PAGE-001",
      "title": "新增物料金额",
      "steps": ["新增测试物料，数量 3、单价 2.50", "在列表中读取该物料金额"],
      "expected": {"AC-031": "7.50"}
    }
  ]
}
```

## 2. 确认页面与准入

- 从 PRD 提取页面名、菜单链、角色及字段或操作等特征。登录后先在用户授权的应用内沿真实导航做只读发现。账号角色和租户需通过 UI 确认。同名入口用导航上下文和页面特征区分。缺入口、权限不足或仍有歧义，记录阻塞并保留证据。
- 预期特征应来自 PRD 或已确认的产品口径。至少用两项独立可见特征，并额外核对角色标记。路由与页面证据同时成立，因为登录页、抽屉、同名页面可能共享 URL。
- 记录浏览器实际 URL，保留路径、查询和哈希路由。跨来源或端口的重定向须单独核实授权。记录当前用例相关的标准路由，导航变化后重新确认。

`pages.json` 示例。快照为清理过个人信息的实际浏览器可见内容，`anchors` 和 `role_marker` 必须出现在快照中。

```json
[
  {
    "id": "PAGE-001",
    "status": "confirmed",
    "entry": "登录 → 物料列表",
    "url": "http://127.0.0.1:8765/",
    "role": "admin",
    "role_marker": "admin(admin)",
    "anchors": ["heading \"物料列表\"", "columnheader \"金额\""],
    "snapshot": "evidence/confirmed-page.txt"
  }
]
```

每条用例操作前和切换页面后，从浏览器重新读取 URL、角色及快照，使用 `qa.py check-page`。页面不符时停止相应操作。页面核对工具校验提供的快照和记录，浏览器实采由执行方负责。

`preflight.json` 记录 `smoke`、`url`、`version`、`sql`、`sql_note`、`evidence`。正式放行要求冒烟为 `passed`，URL 和发布版本与任务一致，有本地证据，并明确 `sql` 为 `verified` 或 `not_applicable` 及依据。缺资料时可出预验收或阻塞报告。P2 缺陷只有取得本版本书面让步才可通过该项门禁，记录其 `waiver` 的 `by`、`reason`、`reference` 和 `version`。

## 3. 记录实测和证据

每项断言保存真实实测值及对应证据。取可复核的业务状态，如回查后的列表行、提示和实际条数。截图可以辅助说明，不能替代状态核对。每个文件使用本次尝试独立的名称，先去除凭据和无关敏感值，再录入。登录密码、会话令牌及真实个人数据不得放入观察文件或截图。

```json
{
  "url": "http://127.0.0.1:8765/",
  "role": "admin",
  "snapshot": "evidence/TC-031-before.txt",
  "assertions": {
    "AC-031": {"actual": "8.50", "evidence": "evidence/TC-031-after.txt"}
  }
}
```

`qa.py record --result` 按 JSON 类型和值比对预期和实测。例中 `8.50` 与 `7.50` 不同，只允许记录 `failed`。缺失、空文件、越界或被修改的证据不计为有效执行。复测另存快照和实测证据。没有必要环境、权限或测试数据时记录 `blocked` 和原因，必测项跳过也会阻塞门禁。

用 `qa.py report` 一次重算统计、门禁及 Markdown 报告。看板按当前结构化记录重新核验。同一运行中不要并行编辑计划、证据与记录。质量门禁仅对已登记的验收范围负责，PRD 被遗漏的行为仍须在评审中补齐。
