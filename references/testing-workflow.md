# 测试工作流程规范（dyd-test 内化版）

主线：需求评审 → 用例设计 → 提测准入 → 测试执行 → 缺陷闭环 → 发布审批与上线 → 上线后收尾。
每阶段有明确输出物与可判断的出口条件。
按 [企业级测试执行指南](enterprise-testing.md) 确定判据、风险和验证层次，按 [验收记录](acceptance-contract.md) 留存证据并计算门禁。

## 三条前置底线

- 需求不清晰、存在矛盾或无法验证时登记待确认点，先推进具备独立验收条件的范围。
- 阻断级缺陷未闭环、遗留缺陷未明确处理人：不发起线上发布审批。
- 环境、增量 SQL、账号权限未就绪：不开始正式执行用例，避免把环境问题误判为功能缺陷。

## 需求评审

- 取得权威需求和相关契约并保留版本与出处。明确业务目标、范围、高风险行为、必须保持的约束及预期来源，拆成可独立验证的条目。
- 对计算、状态流转及角色边界在评审阶段确认判据与适用条件。
- 待确认项按责任人跟踪；答复未落地前对应用例标"待定"，不按推测验收。
- 出口：需求清晰、可实现、可验证；每项口径疑问有答复人或跟踪人。

## 用例设计

- 按 [PRD 验收记录](acceptance-contract.md) 拆独立验收点并保留出处。单条用例写清输入、步骤、逐项预期和测试数据；按风险覆盖正常主流程、边界值、异常失败、角色可见性与回归。
- 按风险选择测试层、独立判据和观察手段，明确应测方向、夹具、预期副作用及清理方式。
- 按项目授权同步测试计划。出口为必测场景、预期与证据采集方式明确，未覆盖项和依赖项有说明。

## 提测准入

- 读取授权发布系统的版本和迁移记录，核对本环境对应的组件版本及增量 SQL 执行凭据或不适用依据。测试在授权范围内核对结果。
- 独立沿实际入口只读勘查，核对路由、角色、租户与页面特征，记录计划和现场差异。确认环境、账号、夹具和观察渠道可用，冻结计划并完成冒烟。
- 出口为已确认版本和环境、冒烟通过及迁移依据齐备。准入缺口交相关负责人处理，具备独立条件的活动按预验收记录。

## 测试执行

- 按风险安排主流程、状态、权限和分层校验，再执行相邻回归及有边界的探索。用真实界面和已授权的非攻击性能力观察同一对象在相关层的结果，按事前确定的判据逐项比对。
- 涉及写入时按 [自主备数与回收](test-data-workflow.md) 在已授权的对象边界内自备数据，先登记基线，写后回查。收尾核验无残留或已归还，结果不明时暂停后续受影响的写入。
- 入口、身份、环境或采集能力缺失时登记受阻方向、影响及解除条件，继续独立用例。体验、无障碍和性能的可复核偏差按影响登记缺陷。

## 缺陷管理

- 缺陷记录原始失败、复现条件、判据来源、实际差异、影响和脱敏证据，按授权流程指派与跟踪。
- 在已确认的修复版本复测原失败，另存证据并关联原缺陷，按复测结果关闭或激活。相邻链路回归单独记录。出口为本轮缺陷处置、遗留风险及责任人明确。

|等级|定义|典型情形|放行要求|
|---|---|---|---|
|P0|安全或生产级严重事故|越权、资金/结算错误、绕过约束、敏感信息泄露|立即阻断发布，修复并回归后方可上线|
|P1|核心链路失败或高概率误导|主流程不可用、金额展示错误、无法提交|修复并回归后放行|
|P2|重要能力不稳定|筛选失效、字段回显错误、报表缺字段|上线前修复或产品书面让步接收|
|P3|体验或展示问题|文案错误、字段顺序、样式异常|登记跟踪，可随后续迭代修复|
|P4|低风险优化项|交互冗余、提示不明确|排入后续优化清单|

- 严重程度按业务影响判定，不按发现难度或控制台日志数量判定。
- 有副作用的缺陷复现前先恢复或准备独立测试状态，禁止盲目重复写入；无法安全重现则保留首次证据标"待复现"。

## 发布审批与上线

- 形成范围内功能结论和正式发布准入结论，引用对应的冒烟、部署、迁移、复测和书面让步凭据。审批通过后由获授权的执行方发布，记录批准与实际发布的凭据、改动、影响范围及需求和缺陷编号。
- 上线后验证核心链路：主流程能走通、关键数据能出来、权限入口可见；数据类核对线上首日与测试环境差异来源。

## 上线后收尾

- 数据巡检：上线后一周每日核对核心口径；出现过中断的口径巡检不短于一周。
- 权限按最小必要配置；上线前完成培训。周报写清统计窗口与数据缺口，统计不出的字段写"未接入，不作估算"。

## 执行记录口径

本地执行数、通过率和门禁按 `execution.jsonl` 的核验结果计算。报告注明分子、分母及范围，与已接入的禅道记录核对并解释口径差异。用验收点与证据说明有效覆盖，列出未完成、不可观测、待确认及夹具残留对结论的影响。
