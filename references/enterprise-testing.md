# 企业级测试执行指南

从业务目标和失败后果出发。对每个关键行为写清执行者与前置条件、预期结果、始终成立的约束和独立验证途径。把每个可独立失败的行为写成验收点，按影响、发生可能性和恢复难度安排测试深度。优先验证可能导致资金或数据错误、权限失控、业务中断或难以恢复的行为。

## 建立可信输入与判据

1. 从用户或项目指定的权威入口获取已批准的需求、规则与原型、接口或事件契约、角色矩阵、提测与迁移记录。按需补取历史缺陷、测试环境、账号与夹具授权。记录来源、责任方、版本或修订时间、适用环境和对应章节。对易变内容保留授权的摘录或快照。账号凭据通过批准的渠道使用，证据只保留角色和脱敏标识。
2. 对齐业务目标、本轮范围、排除项、环境、组件版本、角色与租户，以及受影响的上下游和历史数据。文档、契约、页面与部署记录不一致时，记下冲突及其影响，找对应负责人确认。继续执行具备独立条件的项目。按 [验收记录](acceptance-contract.md) 固定范围、预期和观察点。基准变更时定位受影响用例，按既有规则开启新运行。
3. 先确定测试判据，再观察实测。例如用已批准公式和已知源数据独立计算，用授权的状态迁移表推导终态，用角色矩阵判断允许项和禁止项。将来源与可观察的预期值、时限或阈值绑定到验收点。实际结果可以暴露需求缺口。规则、口径或阈值未确认时保留待确认项，按观察结果报告现象。

## 把风险写入冻结计划

按「目标 → 对象与关联 → 状态表/不变量 → 依赖失败 → 风险 → 独立判据 → 用例」推导。逐项判断重试、并发、边界、异步、事务与补偿、角色隔离、缓存、依赖故障、旧数据与迁移。规则按已确认、待确认、推断风险登记；待确认验收点按原契约保留为 `pending`，继续运行独立可验证场景。

用边界表定义下界前后、命中边界与异常输入；用判定表只保留会改变业务结果的规则组合；用状态转移表列出「源状态 × 动作 × 身份 → 目标状态/拒绝且不变」。将可独立失败的关键转换拆成验收点，下游依赖用 `depends_on` 关联。高风险动作同时登记前置、测试数据、业务标识、证据及独立回查；组合较多时采用成对组合或任务相关的属性、蜕变关系。相同输入、判据和状态且不改变风险覆盖的用例合并为重复采样。

企业验收将 `risk-review.json` 放在运行目录，与需求、用例和页面一起冻结。明确进入本轮的方向，把高风险场景绑定到验收点和执行层。

```json
{
  "schema_version": 1,
  "run_id": "trial-01",
  "version": "v2",
  "source": "prd.md",
  "dimensions": {"data": {"status": "in_scope"}},
  "risks": [{
    "id": "RISK-001",
    "dimension": "data",
    "severity": "high",
    "source": "退款金额不得超过已付款金额",
    "invariant": "同一订单累计退款不超过原实付",
    "impact": "订单与资金流水不一致",
    "scenarios": [
      {"id": "SCN-001", "scenario": "boundary", "layer": "online_ui", "criterion": "AC-001"}
    ]
  }]
}
```

- 维度支持 `functionality`、`data`、`permission`、`integration`、`regression`、`reliability`、`performance` 和 `accessibility`。未评审的维度在报告标明。排除或不适用的维度以 `out_of_scope` 或 `not_applicable` 登记，并指向本轮 `decision` 证据。
- 缺少执行能力时，用 `blocked_layers` 登记独立层名、`reason` 和可用的 `evidence`。此层的高风险会显示未完成，可以继续执行具备条件的独立用例。书面接受剩余风险时，场景的 `acceptance` 引用本轮决策文件。已具备执行能力的高风险必测场景未安排用例时，冻结失败。
- 决策文件包含 `type: "risk_decision"`、`run_id`、`version`、`subject`、`decision`、`by`、`reason`、`reference`。主体使用 `dimension:data` 或 `scenario:RISK-001/SCN-001` 形式。不可执行的场景以 `accepted` 记录剩余风险，仍保留实际未验证状态。最终摘要见 `risk-summary.json`。

## 独立勘查与分层验证

先从需求、状态流转和角色矩阵推导用例，再沿授权的正常入口独立做只读勘查，确认实际路由、角色、租户、页面特征及可观察的上下游。高风险链路用另一种观察途径复核关键结果，例如从独立会话重新查询、查阅获授权的下游记录或使用独立期望计算。记录勘查范围和差异。探索测试设置范围和预算，发现新风险时补验收点或留调查记录。

选择能直接验证规则的最低可用层，并用少量端到端场景连接关键链路。可用时复用既有组件、服务或契约测试，让权限、持久化和跨系统结果在能观测它们的层单独取证。按任务风险评估下列方向，记录适用性、执行条件和剩余缺口。

| 方向 | 执行与判断 |
| --- | --- |
| 功能与正常界面 | 用真实用户入口覆盖主流程、边界、异常、自助恢复和历史数据。逐项检查业务结果，必要时刷新或用另一会话重新读取。 |
| 状态与一致性 | 覆盖合法及受规则拒绝的转换、取消、重提、幂等与失败恢复。核对终态、关联状态和数量等不变量。仅在隔离且获授权时执行并发场景。 |
| 角色与权限 | 使用已授权测试身份，经正常入口验证允许与拒绝、角色及租户可见范围。核对拒绝后相关对象和副作用的状态。缺少相应身份或观察渠道时记录限制。 |
| 集成与数据 | 通过批准的接口、只读数据源或测试接收端，按同一业务标识串联输入、持久化与下游结果。核对契约、异步窗口、重复或缺失、单位、精度和汇总口径。 |
| 体验与无障碍 | 用实际任务检查文案与错误恢复、支持的屏幕和输入方式。按适用标准检查键盘操作、焦点、可访问名称及对比度。记录手工观察和工具能支持的结论范围。 |
| 性能 | 以已批准的阈值、数据规模和环境为基准，先测典型路径。只有负载、窗口和停止条件获授权时才开展负载测试。记录样本、延迟及错误观测。缺少基准时报告实测，阈值验收待确认。 |

执行获授权的正常业务操作、非攻击性的检查及只读观察。工具、账号、环境或数据不足时先寻找能验证同一判据的授权途径，再标明受影响的层、场景、原因和可推进条件。手工检查或外部工具结果也要保留来源与可复核的证据，结论限定在实际观测的层和场景。

## 自主准备数据并闭环副作用

从需求与正常界面识别对象约束、引用和状态；从已核验归属的现有夹具、获授权的测试池或造数入口、正常界面动作依次找可用数据。逐个验证身份、对象归属、唯一标识、隔离性以及允许的写入和回收动作。遇到来源不可用时先尝试下一个已授权来源。对短信、邮件、支付、事件等副作用，事前确认禁用或导向获授权的测试接收端。无法确认时阻塞相关操作。

每次写入登记可复核基线，执行后回查对象及关联结果。超时或结果不明时先回查再决定后续动作。结束或中断后按约删除本轮对象、恢复复用夹具或归还租约，并独立复核关联残留。写入未明或回收未证实的对象保留跟踪记录。登记与回收见 [测试数据流程](test-data-workflow.md) 和 [项目夹具来源](project-test-data.md)。

## 缺陷、复测与覆盖结论

- 将预期来源、操作条件、构建与身份、实际差异、影响和脱敏证据关联到相应用例。业务差异按影响分级。环境、权限配置或判据缺失引起的阻塞也要留证，并登记解除条件。
- 复测在可确认的修复版本和已知数据基线重走失败场景，另存新证据并关联原失败。相邻链路回归单独记录。保留首次失败和复测记录，偶发问题按已证实的复现条件和剩余风险报告。
- 从需求与验收点追踪到风险、必测场景、用例、实测与证据。记录环境、版本、角色、数据标识和观察时点。用结构化执行记录计算分子和分母，列出未覆盖、未完成、阻塞及跳过原因。单列探索发现、工具可观测性及样本覆盖限制。待确认项、计划和示例均保留其实际状态。
- 报告写清本轮范围的功能结论、证据支持的正式发布准入、未闭环风险及责任人。部署与迁移状态引用授权发布记录，遗留缺陷让步引用对应授权决定。审批和实际发布各自以可追溯凭据确认，上线后的验证独立留证。参见 [七阶段流程](testing-workflow.md) 和 [验收记录](acceptance-contract.md)。

## 三个跨业务示例

以下为设计示例。判据来自实际项目确认的规则，示例本身仅用于说明测试设计。

| 场景 | 独立判据与观察方式 | 典型失败模式 |
| --- | --- | --- |
| 订单退款 | 用批准的退款与舍入规则、已知订单明细独立算出应退金额。用授权沙箱走退款，再按订单标识核对退款流水与测试接收端回执。 | 部分退款舍入错误，重试重复退款，界面成功但下游未落账。 |
| 采购审批 | 用角色矩阵和状态表列出申请人、授权审批人及无审批权测试身份的允许动作与终态。通过各自正常入口操作，用授权的审批记录核对每次流转和通知。 | 审批路由错配，无权限的正常业务动作被接受，撤回后仍触发通知。 |
| 库存报表 | 按已确认的出入库与截止时间口径，用已知期初、单据和冲销样本独立算出分仓结存，核对报表及其授权导出。 | 截止时间漏算，冲销重复扣减，汇总正确但分仓归属错误。 |
